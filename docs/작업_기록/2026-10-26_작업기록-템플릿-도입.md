# 작업 기록: 수정 템플릿과 작업 기록 규칙 도입

## 요청

- 프로젝트 수정 시 사용할 수정 방안·방법 템플릿을 마련한다.
- 이 프로젝트에서 작업할 때마다 Markdown 작업 목록/기록을 남긴다.
- Codex도 이후 이 저장소 작업에서 같은 규칙을 따른다.

## 현재 상태와 근거

- 기존 문서 목차는 `docs/프로젝트_기능_설명.md`에 있다.
- 저장소 루트에 작업 기록 규칙을 정하는 `AGENTS.md`는 아직 없다.
- `.gitignore`가 `docs/` 전체를 무시하고 있으므로 기존 문서 파일의 추적 예외가 필요하다.

## 수정 방안

1. 저장소 루트 `AGENTS.md`에 매 작업마다 기록을 먼저 만들고 완료 후 갱신하는 규칙을 둔다.
2. `docs/수정_작업_템플릿.md`에 수정 방안, 작업 체크리스트, 테스트/검증, 결과 및 남은 항목 섹션을 제공한다.
3. 실제 작업 기록은 `docs/작업_기록/YYYY-MM-DD_<작업명>.md`에 저장한다.
4. 이번 요청 자체도 같은 위치에 기록하고, 목차에서 템플릿과 작업 기록 폴더를 안내한다.
5. `.gitignore`에서 문서와 작업 기록 Markdown 파일이 무시되지 않도록 예외를 추가한다.

- [x] 수정 작업 템플릿 작성
- [x] 이번 요청의 기록 파일 작성
- [x] 문서 목차 및 `.gitignore` 갱신
- [x] 변경 결과와 Git 추적 상태 확인

## 검증

- Markdown 파일 목록 및 문서 목차 내부 링크를 확인했다.
- `.gitignore` 예외를 추가해 루트 지침, 문서 템플릿, 날짜별 기록이 Git에 표시되는 것을 확인했다.
- 프로젝트 빌드/테스트는 지침과 문서만 추가한 작업이므로 실행하지 않았다.

## 변경 파일

- `AGENTS.md` — 향후 저장소 작업의 기록 규칙 추가
- `.gitignore` — docs 루트 및 작업 기록 폴더의 Markdown 예외 추가
- `docs/수정_작업_템플릿.md` — 수정 방안과 체크리스트 양식
- `docs/작업_기록/README.md` — 기록 폴더 안내와 목록
- `docs/작업_기록/2026-10-26_작업기록-템플릿-도입.md` — 이번 작업 기록
- `docs/프로젝트_기능_설명.md` — 템플릿과 작업 기록 목차 링크

## 결과

완료. 이후 이 저장소에서 프로젝트 작업을 수행할 때마다 먼저 날짜별 Markdown 기록을 만들고, 마무리 시 검증 결과와 상태를 갱신한다.
