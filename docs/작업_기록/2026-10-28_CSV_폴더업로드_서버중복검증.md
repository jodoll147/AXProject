# 작업 기록: CSV 폴더 일괄 적재와 서버 중복 검증

## 요청
- CSV를 폴더째 또는 단일 파일로 업로드할 수 있도록 개선하고, 백엔드에서 중복 검증을 강화한다.

## 현재 상태와 근거
- 기존 단일 파일 업로드는 UI 미리보기와 서버 PK 중복 검증을 수행하나 폴더 업로드와 다중 파일 전체 원자성은 없다.
- 데이터와 감사는 AppStore의 단일 파일에 저장하며 현재 API는 테이블별 순차 처리다.
- 기준 명세 Excel 및 기존 사용자 변경은 보존한다.

## 수정 방안
1. 여러 CSV를 폴더로 선택하고 파일명/헤더에 따라 테이블을 식별해 기존 단일 업로드를 유지한다.
2. 서버에서 모든 파일을 참조 순서로 검증하고 기존/배치 내 중복을 식별해 오류 시 전부 취소한다.
3. 정상 배치는 데이터와 감사이력을 함께 한 번만 저장한다. 사용자에게 파일·행별 오류를 표시한다.
4. 격리된 API 테스트와 브라우저 화면, 빌드 및 문서를 검증한다.

## 검증과 결과
- dotnet build app/backend/AxBackend.csproj -o app/backend/bin/batch-debug --no-restore: 성공. 실행 중인 DLL 잠금으로 재시도 경고가 발생해 해당 개발 서버를 중지한 뒤 빌드 성공(오류 0).
- npm --prefix app/frontend run build: 성공.
- node --test work/tests/*.test.mjs: 20개 통과. 격리된 임시 데이터에서 미인증/VIEWER 거부, 역순 참조 처리, 검증만 실행 시 무변경, 파일 간 PK 중복, 잘못된 FK 전체 취소, 정상 일괄 저장과 감사, 기존 실적 중복/다른 ID 중복, 동시 중복 요청 중 한 건만 저장 확인.
- 실제 제품 브라우저에서 목업 폴더 15개 파일의 테이블 판별과 파일·행별 중복 오류 및 전체 업로드 버튼 비활성 확인. 기존 단일 파일 미리보기 및 중복 표시 확인.
- 임시 CSV 2개 폴더의 정상 서버 검증 통과 및 업로드 버튼 활성 확인. 검증만 실행하고 실제 제품 데이터에 시험 자료를 저장하지 않았으며 임시 파일 제거.
- 개발 서버 5299를 확인한 프로젝트 프로세스만 새 빌드로 재시작하고 5298 화면에서 확인.
- 문서 목차 및 관련 링크, git diff --check 확인. 원본 요구사항 Excel 미수정.

## 남은 항목과 제약
- 동일 작업·시작/종료·수량·단위가 같은 생산실적은 ID나 데이터 출처가 달라도 중복으로 거부한다. 실제 업무상 동일 값의 별개 실적을 허용해야 한다면 중복 기준을 별도 협의해야 한다.
- 폴더 모드에서 셀 편집은 제공하지 않으며 오류 파일을 외부에서 수정해 다시 선택한다. 브라우저의 폴더 선택 지원이 필요하다. 단일 파일 셀 편집은 유지된다.
- 저장 잠금은 단일 서버 프로세스 범위다. 다중 프로세스/운영 DB 트랜잭션과 장애 주입은 이번 범위 밖이다.
- Git 커밋·푸시는 수행하지 않았다.
