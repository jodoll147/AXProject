# 작업 기록: CSV 사전 검증·표 편집 후 업로드

## 요청

- CSV를 선택하면 즉시 적재하지 않고 중복·형식·참조를 먼저 검증한다.
- CSV 내용을 데이터 표에 표시하고, 정상 셀은 초록색·오류 셀은 빨간색으로 표시한다.
- 오류 셀을 화면에서 수정한 뒤 별도 업로드 버튼으로 저장한다.

## 현재 상태와 근거

- `work/screen_template.html`의 `handleFile`은 CSV를 검증하고 오류가 없으면 즉시 `/api/data/upload`를 호출한다.
- `validate`는 행·필드별 오류를 반환하지만 원본 CSV 표와 셀 편집 UI가 없다.
- 서버는 적재 요청 시 다시 필드·자료형·필수값·중복 키·참조를 검증한다.

## 수정 방안

1. 파일 선택 단계에서 CSV 행을 메모리에 보관하고 표로 렌더링한다.
2. 기존 검증 결과를 각 셀에 매핑해 색과 오류 이유를 표시한다. 셀 편집 후 전체 검증을 다시 실행한다.
3. 별도 업로드 버튼에서만 서버 적재 API를 호출한다. 오류가 남아 있으면 버튼을 막고, 서버 오류도 표에 반영한다.
4. 현재 적재 데이터와 기존 이력은 보존하고 빌드·브라우저에서 정상·오류·수정 흐름을 확인한다.

## 검증

- `npm run build` (`app/frontend`) 성공.
- 인라인 스크립트 구문 검사 성공.
- 검증 함수 독립 검사: 이미 적재된 PK 중복, 잘못된 정수, 정상 행, 빈 파일, 초과 열을 확인.
- 업로드 흐름 독립 검사: 파일 선택 단계에서는 서버 요청 0회, 명시적 버튼 처리에서 1회 요청 확인.
- 로컬 서버 실행: 백엔드 `127.0.0.1:5182`, 프런트엔드 `127.0.0.1:5173`. 브라우저에서 새 업로드 화면 문구와 데이터 상태 로딩 확인.
- 브라우저 파일 선택 후 표 색상·편집의 끝단 시각 검증은 브라우저 자동화 중 경로가 바뀌어 완료하지 못함.
- 기존 `app/backend/local-data.json`의 길이와 수정 시각은 검사 전후 동일함(113,965바이트, 10:42:06).

## 남은 항목과 제약

- 사용자가 실제 브라우저에서 CSV를 선택해 표 색상과 수정 동작을 최종 확인해야 함. 자동화 검증은 완료하지 못함.

## 결과

구현 완료. CSV 선택과 서버 적재를 분리했고, 셀별 검증 결과를 편집 가능한 표에 표시한다. 오류가 없을 때만 업로드 버튼이 활성화되며 서버 오류도 다시 표에 표시한다. 기존 적재 데이터는 변경하지 않았다.
