# 작업 기록: 로그인·권한·감사 및 업로드 검증 구현

## 요청

- 지금까지 정리한 로그인, Settings 권한관리, 감사이력 및 서버 업로드 검증 설계와 기능을 구현하고 보고한다.
- 관리자만 역할별 권한과 계정 배정을 관리한다. 서버 운영요약은 이전 요청에 따라 범위에서 제외한다.

## 현재 상태와 근거

- `work/screen_template.html`: 로그인 준비 화면과 클라이언트 역할 선택만 존재한다.
- `app/backend/Program.cs`: 인증·인가·영구 감사 없이 JSON 데이터와 기본 업로드 검증을 제공한다.
- `docs/서버_업로드_검증_구현_계획.md`, `docs/엑셀_권한_확인과_3역할_설계안.md`: 설계 및 미확정 정책.

## 수정 방안

1. 기존 데이터 보존과 원자적 감사 저장을 고려해 인증·세 역할·계정·담당 배정을 구현한다.
2. 서버 업로드 검증 및 관리자 전용 Settings·감사 화면과 담당 입력을 연결한다.
3. 격리된 데이터로 API와 화면을 검증하고 문서에 제약을 명시한다.

## 검증

- 실행: `dotnet build --no-restore`, Vite 직접 빌드 및 인라인 스크립트 구문 검사, `app/backend/tests/run-integration.ps1` 격리 API 테스트. 브라우저에서 관리자 로그인·Settings·계정 추가와 조회자 로그인·설정 제한 확인.
- 결과: 백엔드·프런트엔드 빌드 통과. 미인증·권한 부족, 담당 범위, 역할 권한 변경, 마지막 관리자 보호, 세션 무효화, 로그인 횟수 제한, 잘못된 배치 거부, 담당 실적 등록·수정, 초 단위 보존, 감사 필터 및 재시작 후 계정·데이터·감사 보존, 초기화·샘플 복원 테스트 통과. 기존 사용자 `local-data.json`과 엑셀은 테스트에서 변경하지 않았다.
- 실행하지 않은 검증: 정전·디스크 장애 강제 주입과 다중 프로세스 동시 쓰기, 모든 화면 크기의 시각 검증. 테스트 중 분리된 로컬 서비스와 테스트 전용 계정을 사용했다.

## 남은 항목과 제약

- 자동 승인 검토가 선행 작업의 동일 블록 강제와 재작업의 품질 사건 강제를 정상 데이터 거부 위험 및 정책 미확정으로 거부하여 해당 규칙은 미구현이다.
- 현재 저장은 단일 프로세스 로컬 JSON 방식이며, 쿠키 키 파일 암호화·TLS·다중 프로세스 운영, 감사 보존 정책과 계정 복구는 별도 설계가 필요하다.
- 기존 요구 대조에서 지적한 좌표 기반 배치, 과거 재생 UI, 계획 테이블의 기간별 비교는 이번 인증·권한·적재 구현에서 변경하지 않았다. 서버 운영요약은 이전 사용자 지시에 따라 제외했다.

## 결과

부분 완료. 로그인, Settings, 세 역할과 서버 인가, 담당 입력, 기본 업로드 검증과 영구 감사이력을 구현하고 검증했다. 추가 업무 관계 규칙은 승인 보류로 남았다.
