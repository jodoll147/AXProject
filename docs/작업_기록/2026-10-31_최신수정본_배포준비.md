# 작업 기록: 최신 수정본 배포 준비

## 요청

- 로컬에서 검증한 최신 수정본을 배포한다.

## 현재 상태와 근거

- GitHub main 기준: `5c4cc47`.
- 기존 Sites URL은 버전 1이다. Sites는 Cloudflare Workers에서 서버 코드를 실행하며 ASP.NET Core 런타임을 제공하지 않는다.
- 현재 연결된 .NET 배포 서버나 호스팅 계정은 확인되지 않았다. 사용자에게 배포 대상을 문의했다.

## 수정 방안

1. ASP.NET Core에서 빌드된 프론트엔드를 제공하도록 구성한다.
2. 프론트·백엔드를 함께 빌드하는 Dockerfile과 영구 저장소 구성을 준비한다.
3. 실제 인증·저장 동작을 검증하고 배포 대상이 확인되면 배포한다.

## 작업 목록

- [x] 기존 Sites 런타임과 현재 배포 버전 확인
- [x] 단일 서버 배포 구성
- [x] .NET publish 및 단일 서버 HTTP 검증
- [ ] Docker 이미지 전체 빌드 (레지스트리 네트워크 차단)
- [ ] 배포 대상 확인 및 실제 배포

## 결과

부분 완료. 프론트·API를 함께 제공하는 코드, Dockerfile, .dockerignore 및 서버 배포 문서를 준비했다. main에 커밋·push한다. 현재 사이트는 갱신하지 않았다.

## 검증

- .NET Release publish 성공.
- 배포 디렉터리에 실제 프론트 dist를 배치하고 단일 .NET 프로세스로 `/`, 로그인, 관리자 조회, CSV 항목 명세, 로그아웃 및 익명 세션을 확인했다. 모두 통과했다.
- Docker 로컬 데몬 정상 확인 후 BuildKit CA secret을 제공하여 빌드를 시도했다. Microsoft Container Registry가 리다이렉트하는 `centralus.data.mcr.microsoft.com`의 다운로드가 Forbidden으로 차단되어 이미지 검증은 미완료다. 네트워크 정책을 우회하지 않았다.
- `git diff --check`는 저장소 CRLF를 고려한 `core.whitespace=cr-at-eol` 설정으로 통과했다.
- 기존 상태·실계정과 분리한 임시 파일로 검증했고 테스트 서버는 종료했다.

## 남은 항목

- .NET 실행이 가능한 배포 서버/호스팅 계정과 HTTPS 인그레스 구성이 필요하다. 사용자 응답 대기 중이다.
- 기존 Sites 프로젝트의 공개 범위와 배포 버전은 변경하지 않았다.
- 현재 작업 환경에 Sites 필수 source helper도 설치되어 있지 않다. 다만 그 도구가 있더라도 .NET 서버 자체를 Workers에서 그대로 실행할 수는 없다.
