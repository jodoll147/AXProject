# 작업 기록: 데이터 파일 Git 추적 제거

## 요청

- 이미 푸시한 목업 CSV·ZIP과 엑셀 파일을 Git 및 원격 기록에서 제거한다.

## 현재 상태와 근거

- 관련 파일/기능: `outputs/조선_AX_목업데이터_CSV.zip`, `outputs/조선_AX_목업데이터_CSV/`, `엑셀 파일/*.xlsx`, `.gitignore`
- 현재 동작 또는 문제: CSV·ZIP은 방금 푸시한 `a848882`에 포함됐고, 엑셀 파일 3개는 과거 첫 커밋 `e8d8e16`부터 추적 중이다. 원격에는 `main` 브랜치 하나가 있고 태그는 없다.
- 미확인 사항: 없음

## 수정 방안

1. 데이터 파일이 로컬 디스크에 남도록 보존하면서 Git 추적에서 제외한다.
2. `.gitignore`에 엑셀·목업 CSV 산출물 제외 규칙을 추가한다.
3. 관련 Git 기록을 재작성하고 `--force-with-lease`로 원격 `main`을 갱신한다.

- `README.md`, `app/README.md`, `docs/데이터베이스.md`, `docs/개발과_범위.md`, `docs/프로젝트_기능_설명.md` — 로컬 데이터 준비 안내

## 검증

- 실행: `git ls-files` 데이터 경로 확인, `git log --all` 경로 검사, `git status`, `git check-ignore`, 로컬 엑셀·CSV·ZIP 존재 검사, 원격 `main` 상태 확인
- 결과: 재작성된 `main`의 커밋 기록 및 모든 현재 참조에 데이터 파일이 없고, 원격 `main`을 강제 갱신했다. 로컬 엑셀 3개·CSV 15개·ZIP은 보존됐으며 제외 규칙이 적용된다.
- 실행하지 않은 검증: 기능 코드는 변경하지 않아 빌드·통합 테스트는 다시 실행하지 않음.

## 남은 항목과 제약

- GitHub에서 이전 커밋 SHA로의 접근이나 캐시가 즉시 사라지는 것은 보장되지 않는다. 서버 측 별도 정리가 필요할 수 있다.
- 로컬 Git의 전체 reflog 즉시 만료 명령은 자동 승인 심사가 관련 없는 커밋 복구 기록까지 제거한다는 이유로 거부했다. 이전 커밋의 로컬 reflog/객체는 남아 있을 수 있다.

## 결과

부분 완료. `main`의 전체 커밋에서 엑셀 3개와 목업 CSV 15개·ZIP을 제외하고 원격 브랜치를 갱신했다. `.gitignore`가 엑셀·CSV·ZIP 데이터 파일의 재추적을 막는다. GitHub의 이전 SHA·캐시와 로컬 reflog/객체의 완전 삭제는 확인하지 못했다.
