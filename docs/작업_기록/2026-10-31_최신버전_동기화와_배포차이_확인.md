## 변경 파일

- `work/sync_frontend.mjs`: 로그아웃 응답을 검사하고 실패 시 재시도 안내. 중복 요청 차단.
- `work/screen_template.html`: 설정·담당 입력 탭 활성 표시. CSV 단일/다중 저장 성공 이후 sessionStorage 오류가 저장 실패로 표시되지 않도록 처리.
- `app/frontend/index.html`: 원본 템플릿과 생성 스크립트에서 재생성.
- `app/backend/Program.cs`: 만료·무효 세션도 로그아웃 가능하게 처리. 로그아웃의 변경 요청 헤더 검사는 유지. 인증 응답은 no-store.
- `work/tests/session_controls.test.mjs`: 생성된 실제 화면 코드로 로그아웃 성공/실패/중복 및 CSV 기록 저장 오류 회귀 검증.
- `app/backend/tests/integration.py`: 만료 세션 로그아웃, 헤더 누락 거부, 반복 로그아웃, 세션 캐시 방지 검사.
- `README.md`: 개발 프록시와 운영 배포 구성 차이를 명시.

## 검증

- `pnpm install --frozen-lockfile`, `pnpm build`: 성공.
- .NET 10 `dotnet build`: 성공, 경고 0·오류 0.
- 기존 Node 회귀 테스트 18건, CSV 일괄 업로드 API 테스트 1건 통과.
- 생성된 화면의 로그아웃·CSV 오류 처리 회귀 테스트 4건 통과.
- Python 실제 API 통합 테스트와 재시작 후 저장 검증 통과: 권한, 담당 배정, CSRF, 잘못된 CSV, 역할 변경 시 세션 무효화, 로그아웃, 요청 제한, 감사, 초기화·복원.
- 테스트는 별도 임시 상태 파일을 사용했다. 원본 엑셀은 기존 체크아웃에서 Git 제외 경로로 복사했으며 커밋하지 않는다.
- 초기 일반 샌드박스 실행은 Node 내부 오류 및 .NET 프로세스 잠금 오류로 실패했다. 허용된 실행 권한으로 재검증해 위 결과를 확인했다.
- 브라우저 UI 및 실제 배포 URL의 동작 검증은 실행하지 않았다.

## 남은 항목과 제약

- 배포 갱신은 미완료. Sites 필수 source helper가 현재 실행 환경에 없으며, skill resource 경로로도 확보하지 못했다.
- 최신 ASP.NET Core 백엔드를 Sites에서 그대로 실행할 수 있는지 검증하지 않았다. 프론트엔드만 교체해 인증·저장을 구현한 것으로 처리하지 않는다.
