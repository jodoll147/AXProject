# 작업 기록: 목업 엑셀의 CSV 변환과 업로드 안내

## 요청

- 제공된 `조선_AX_목업데이터 - 복사본.xlsx`가 업로드되지 않는 원인을 확인한다.
- 사용자 수정 요청에 따라 업로드는 CSV 전용으로 유지하고, 제공 파일의 15개 시트를 각각 CSV로 변환한다.

## 현재 상태와 근거

- 업로드 입력 `work/screen_template.html`은 `.csv,text/csv`만 허용하고, 선택 파일을 CSV 텍스트로 파싱한다.
- 제공된 파일은 `vessels`부터 `equipment_snapshot`까지 현재 API와 같은 이름의 15개 시트를 가진 `.xlsx`다.
- 현재 백엔드는 테이블 하나씩 JSON 행을 추가하는 CSV API만 제공한다. 기존 화면은 `.xlsx`를 끌어놓으면 바이너리를 CSV 텍스트로 해석해 엉뚱한 헤더 오류를 표시했다.

## 수정 방안

1. 업로드 화면에서 CSV 확장자만 처리하고 다른 파일은 명확한 안내와 함께 거부한다.
2. 제공 통합 문서의 15개 시트를 참조 순서에 맞춘 개별 UTF-8 CSV로 저장한다. 날짜 시각은 `+09:00` 형식으로 변환한다.
3. 원본 값과 변환 결과를 대조하고, 압축 파일로 묶어 전달한다. 로컬 화면 데이터는 변경하지 않는다.

## 변경 파일

- `work/screen_template.html`, `app/frontend/index.html` — `.xlsx` 업로드 시 CSV 전용 안내를 표시하고 이전 실패 이력도 같은 안내로 정리.
- `outputs/조선_AX_목업데이터_CSV/` — 시트별 CSV 15개. 파일명 숫자는 업로드 순서.
- `outputs/조선_AX_목업데이터_CSV.zip` — 15개 CSV 묶음.
- `work/csv_conversion_20261026/` — 동일 변환을 재실행·검증하는 스크립트.
- `README.md` — CSV 전용 형식 안내.

## 검증

- `npm run build` (`app/frontend`) 통과.
- 원본 엑셀과 15개 CSV의 모든 헤더·행·값을 대조해 일치 확인. 날짜 시각은 `yyyy-MM-ddTHH:mm:00+09:00`, `plan_date`는 날짜 형식으로 확인.
- 압축 파일 안에 CSV 15개가 모두 있는지 확인.
- 로컬 브라우저에서 `.xlsx`의 이전 실패 이력이 `CSV 전용` 안내로 보이고 데이터는 여전히 15개 테이블 0건임을 확인.
- `git diff --check` 통과.

## 남은 항목과 제약

- CSV는 테이블별로 순서대로 올려야 한다. 실제 업로드는 사용자가 시험할 수 있도록 수행하지 않았다.

## 결과

완료. 원본 통합 문서는 변경하지 않았고 CSV 15개와 압축 파일을 생성했다. 백엔드 엑셀 업로드 기능은 추가하지 않았다.
