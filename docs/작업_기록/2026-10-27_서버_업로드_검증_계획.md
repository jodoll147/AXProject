# 작업 기록: 서버 업로드 검증 계획

## 요청

- 서버 업로드 검증의 작업 우선순위와 상세 구현 범위를 정리한다.

## 현재 상태와 근거

- 관련 파일: `app/backend/Program.cs`, `work/screen_template.html`, 엑셀 요구사항 대조 보고서.
- 서버는 일부 기본 검증을 수행하고 화면에는 추가 검증이 있으나 서버에 같은 업무 규칙이 없다.
- 미확인 사항: 선후관계 등 일부 업무 규칙의 실제 운영 정책.

## 수정 방안

1. 현재 서버·화면 검증을 확인하고 서버 보강 우선순위를 정한다.
2. 규칙별 적용 범위, 예외, API 응답 및 검증 방법을 계획서로 작성한다.
3. 불확실한 업무 정책을 구분하고 문서 목차를 갱신한다.

## 검증

- 실행: 서버 업로드 코드와 화면 검증 코드, 요구사항 대조 보고서 및 문서 목차 확인.
- 결과: 기본 검증, 저장 원자성, 화면과 서버의 업무 검증 차이, PK 겸 FK 검증 누락과 시간 저장 시 초 손실을 계획에 반영했다.
- 실행하지 않은 검증: 코드 변경이 없는 계획 수립이므로 빌드·API 테스트는 실행하지 않았다.

## 남은 항목과 제약

- 선후관계, 동일 시각, 수량 상한 등 운영 정책은 구현 전에 확인해야 한다.

완료. P0~P3 순위와 규칙별 구현 범위, 기존 데이터 보호 및 테스트 완료 기준을 계획서로 정리했다.
