# 수정 작업 계획 및 기록 템플릿

아래 내용을 복사해 `docs/작업_기록/YYYY-MM-DD_<작업명>.md`에 저장합니다. 작업 시작 시 요청과 수정 방안, 체크리스트를 먼저 채우고 작업 종료 시 결과와 검증을 갱신합니다.

```markdown
# 작업 기록: <작업 제목>

## 요청

- <사용자가 요청한 결과>

## 현재 상태와 근거

- 관련 파일/기능: `<경로>`
- 현재 동작 또는 문제: <코드/문서 확인으로 파악한 사실>
- 미확인 사항: <없으면 없음>

## 수정 방안

1. <변경할 내용과 위치>
2. <필요한 데이터/API/UI 영향>
3. <호환성·기존 동작 고려사항>

## 작업 목록

- [ ] <조사 또는 준비>
- [ ] <구현/문서 수정>
- [ ] <검증 및 검토>
- [ ] 작업 기록의 결과/상태 갱신

## 변경 파일

- `<경로>` — <변경 이유>

## 검증

- 실행: `<명령 또는 확인 방법>`
- 결과: <성공/실패와 핵심 출력>
- 실행하지 않은 검증: <없으면 없음과 사유>

## 남은 항목과 제약

- <없으면 없음>

## 결과

<완료/부분 완료/중단 및 실제 결과 요약>
```

## 계획을 세울 때

- 구현 전에 관련 파일과 기존 프로젝트 규칙을 읽고 현재 상태를 근거와 함께 정리합니다.
- 변경은 요청을 충족하는 범위로 나누고 사용자 데이터, API 계약, 화면 동작의 영향을 작업 목록에 포함합니다.
- 삭제/대규모 구조 변경처럼 되돌리기 어려운 선택은 대안과 영향도 기록합니다.
- 테스트나 빌드를 실행하지 않은 경우 통과한 것처럼 쓰지 않습니다.

## 마무리할 때

- 체크리스트를 실제 결과에 맞게 완료 처리합니다.
- 변경 파일과 실행한 검증/결과를 기록합니다.
- 미완료 항목, 외부 제약, 검증하지 않은 부분을 명시하고 상태를 `완료`, `부분 완료`, `중단` 중 하나로 적습니다.
