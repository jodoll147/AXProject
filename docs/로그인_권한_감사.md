# 로그인·권한·감사

## 로컬 최초 실행

기존 계정이 없을 때만 환경변수로 최초 관리자를 생성한다. 비밀번호는 12자 이상이어야 한다. 아래 명령은 백엔드 실행 터미널에서 한 번 사용하며 값은 코드나 설정 파일에 기록하지 않는다.

```powershell
$env:AX_ADMIN_LOGIN = Read-Host '최초 관리자 아이디'
$env:AX_ADMIN_PASSWORD = Read-Host '최초 관리자 비밀번호 (12자 이상)' -MaskInput
dotnet run --project app/backend/AxBackend.csproj --urls http://127.0.0.1:5182
```

로컬 개발 테스트에서만 `ASPNETCORE_ENVIRONMENT=Development`와 `AX_ALLOW_SHORT_DEV_ADMIN_PASSWORD=1`을 함께 설정하면 최초 관리자에 한해 12자 미만 비밀번호를 허용한다. 이 예외는 운영 환경과 일반 계정에는 적용되지 않는다. 짧은 비밀번호는 테스트에만 사용하고 실제 운영에는 사용하지 않는다. 최초 관리자 생성 후에는 이 환경변수가 필요하지 않다.

서버를 종료한 뒤 해당 터미널에서 `Remove-Item Env:AX_ADMIN_LOGIN,Env:AX_ADMIN_PASSWORD`로 변수를 지울 수 있다. 초기 계정이 이미 있으면 환경변수는 계정을 변경하지 않는다. 계정이 없는 상태에서 환경변수가 없으면 로그인 화면에 초기 설정 안내가 표시된다. 프런트엔드는 별도 터미널에서 기존 실행 절차대로 시작한다.

기본 저장 파일은 Git에서 제외되는 `app/backend/app-state.json`이다. 쿠키 암호화 키는 `app/backend/data-protection-keys/`에 저장된다. 사용자는 이 파일과 키를 안전하게 백업하고 접근을 제한해야 한다. 테스트 환경에서는 `AX_STATE_PATH`, `AX_KEY_DIR`로 별도 경로를 지정할 수 있다. 현재 구현은 단일 프로세스의 로컬 개발용이며, 키 파일 암호화·TLS·배포 환경과 다중 프로세스 동시성은 운영 적용 전에 별도 구성과 검증이 필요하다.

## 역할과 Settings

세 역할은 `VIEWER`, `WORKER`, `ADMIN`이다. 기본값으로 조회자는 조회, 작업담당자는 조회와 배정된 작업의 실적·사건 입력, 관리자는 모든 기능을 사용할 수 있다. 관리자는 Settings에서 조회자와 작업담당자의 담당 입력·데이터 적재 권한을 변경할 수 있다. 조회 권한과 관리자 관리 권한은 고정한다. 역할 설정과 계정 관리, 감사 조회 API는 관리자만 호출할 수 있다.

Settings에서 계정을 만들고, 역할·활성 여부·담당 작업을 수정한다. 새 비밀번호는 12자 이상이며 서버의 ASP.NET Core 비밀번호 해시로 저장한다. 역할·활성 여부 또는 비밀번호 변경 시 기존 세션을 무효화한다. 마지막 활성 관리자의 강등·비활성화는 막는다. 담당 실적과 사건의 등록·수정은 서버에서 기존/요청 작업지시와 배정 목록을 확인한다. 데이터 입력과 수정은 현재 서버 재로딩 후 화면 집계에 반영된다.

로그인 성공 시 HttpOnly, SameSite=Strict 쿠키를 발급한다. 모든 변경 요청은 `X-Requested-With: AXProject` 헤더가 필요하며, 로그인은 IP당 분당 10회로 제한한다. 서버가 현재 활성 계정과 역할을 매 요청 확인한다. 인증 없는 요청은 401, 권한 부족은 403이다. 실제 운영 환경의 인증 정책, 계정 복구, 세밀한 담당 배정, 감사 보존기간은 확정이 필요하다.

## 저장 및 감사

처음에는 기존 `local-data.json`이 있으면 이를 읽고 없으면 샘플 엑셀을 읽는다. 새 계정 생성이나 데이터 변경 시 별도 `app-state.json`에 계정, 역할 설정 및 감사가 저장되며, 업무 데이터 변경 시 데이터와 감사이력을 같은 파일의 임시 교체 작업으로 저장한다. 기존 `local-data.json`과 샘플 엑셀은 덮어쓰지 않는다. 로컬 파일 교체와 프로세스 잠금은 단일 프로세스 기준이며 정전·디스크 장애 복구는 검증하지 않았다.

계정 생성·변경, 역할 권한 변경, 업로드·담당 입력·초기화·복원에 수행자 ID, 시각, 대상과 전후 데이터를 남긴다. 비밀번호와 쿠키는 감사 기록에 넣지 않는다. 관리자 Settings에서 최근 최대 200건을 보고 수행자 ID·작업·대상·기간으로 검색할 수 있다. 실패·권한 거부 요청의 감사 기록과 삭제·보존 정책은 아직 제공하지 않는다.

## 검증 범위

업로드는 기본 필드·참조·키 외에 상태, 시간 순서, 단위, 생산계획 1건, 실적 음수 및 검사 수량을 서버에서 검사한다. 선행 작업의 동일 블록 여부·재작업의 품질 사건 연결 등 추가 업무 규칙은 정상 데이터에 영향을 줄 수 있어 정책 확정이 필요하다. 자동 승인 검토가 이 두 규칙의 강제를 거부했으므로 현재 구현하지 않았다.

`app/backend/tests/run-integration.ps1`은 격리된 상태 파일과 테스트 계정을 사용한다. 로컬 포트 5199가 사용 가능해야 하며 Python 3이 필요하다. 예: `./app/backend/tests/run-integration.ps1 -Python python`. 이 테스트는 실제 `local-data.json`을 수정하지 않는다.
