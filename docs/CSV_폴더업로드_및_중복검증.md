# CSV 파일·폴더 업로드 및 중복 검증

## 사용 방법

1. 데이터 업로드 화면에서 `CSV 파일 선택`으로 파일 하나 또는 여러 개를 선택하거나 `CSV 폴더 선택`으로 폴더를 선택한다. 폴더의 하위 폴더도 포함되며 CSV가 아닌 파일은 제외한다. 브라우저의 폴더 선택 지원이 필요하다.
2. 파일 하나는 기존 표 미리보기에서 셀을 확인·수정하고 업로드할 수 있다. 폴더 또는 여러 파일은 파일명·판별된 테이블·행 수를 확인한다. 폴더 모드의 CSV 셀은 화면에서 수정하지 않으므로 오류가 있으면 원본 CSV를 수정해 다시 선택한다.
3. 여러 파일은 `서버 검증`을 누르고 오류가 없으면 `전체 업로드`를 누른다. 서버는 저장 시 다시 검증한다. 새 파일이 서버 데이터를 참조하는 순서와 다르게 선택돼도 참조 순서로 검증한다.
4. 검증 오류는 파일명·행·필드·사유로 보여 준다. 최대 50건을 화면에 표시하며, 하나라도 오류가 있으면 전체 배치를 저장하지 않는다. CSV가 아닌 파일의 제외 개수도 표시한다.

## 서버 처리와 중복 기준

- 각 파일의 헤더를 확인하고 같은 테이블의 여러 파일을 하나의 검증 배치로 합친다. 기존 데이터와 같은 요청의 앞선 참조 테이블을 기준으로 각 행의 필수값·자료형·PK·FK·단위·상태·시간·수량 등을 검사한다.
- **기본키**는 이미 저장된 행, 같은 파일, 같은 테이블의 다른 파일을 모두 확인해 중복이면 거부한다. 생산계획은 작업지시당 1건 제한도 확인한다.
- **생산실적**은 실적번호가 달라도 작업지시·집계 시작·집계 종료·신규 인정수량·단위가 모두 같으면 중복으로 거부한다. 시간 표현과 숫자 표현이 달라도 같은 값이면 중복이다. 데이터 출처만 다른 경우에도 거부한다. 이 기준은 단일 업로드와 담당 실적 입력에도 적용된다.
- 동일 작업·구간·수량·단위의 별개 실적을 실제로 두 건 저장해야 하는 업무에는 위 기준이 제한이 될 수 있다. 자동으로 합산하거나 덮어쓰지 않는다. 허용해야 할 예외는 업무 기준을 정해야 한다.
- 임시 데이터 복사본에서 전체를 검증한 후에만 한 번 저장하고 `upload:batch` 감사이력을 함께 남긴다. 검증 또는 저장 실패 시 일부 파일만 반영하지 않는다. 저장 요청은 동일 서버 프로세스의 잠금 안에서 다시 검사하므로 동시에 같은 데이터가 들어와도 한 건만 허용한다.
- 현재 저장소는 단일 서버의 로컬 파일이다. 다른 프로세스/서버 사이의 동시 쓰기 보장이나 운영 DB 트랜잭션은 제공하지 않는다.

## API 및 범위

- `POST /api/data/batch/validate`: `{ "files": [{ "name", "table", "headers", "rows" }] }` 검증만 수행. 저장과 감사 변경 없음.
- `POST /api/data/batch`: 같은 입력을 다시 검증하고 전부 저장. 파일 1~100개. 접근은 기존 데이터 업로드 권한으로 제한.
- `POST /api/data/upload`: 기존 단일 파일 API. 기본키 및 같은 생산실적 내용에 대한 서버 중복 검증을 수행.
- 폴더/여러 파일에 대한 UI 사전 테이블 판별은 헤더를 사용한다. 파일별 헤더는 서버가 명세와 대조하므로 잘못 판별된 파일은 거부된다.
- 원본 요구사항 Excel은 바꾸지 않았다. 폴더 업로드·내용 기반 중복 검사는 사용자 추가 요청이다.

## 검증

격리된 임시 서버/데이터로 파일 간 PK 중복, 이미 존재하는 PK, 서로 다른 실적번호의 중복 내용, 누락된 참조, 전체 취소, 참조 순서 역전, 검증만 실행 시 무변경, 성공 감사 기록, 미인증·권한 거부, 동시 중복 요청을 확인했다. 실제 제품 브라우저에서 기존 목업 폴더 15개 파일의 테이블 판별과 중복 오류·저장 차단, 단일 파일 미리보기를 확인했다. 상세 기록은 [작업 기록](작업_기록/2026-10-28_CSV_폴더업로드_서버중복검증.md)을 참고한다.
