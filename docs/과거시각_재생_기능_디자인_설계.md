# 과거 기준시각 선택·재생 — 기능 및 디자인 설계

> **최신 결정:** 이후 사용자 논의에서 과거 조회를 메인에서 제외하고 조회 탭의 블록·작업·설비 상세에 배치하기로 했다. 최신 준비본과 확정할 항목은 [기존 화면 기반 재디자인](화면_재설계_디자인_보고.md)을 기준으로 한다. 아래 메인 패널·블록 표 중심 내용은 이전 시안의 설계 이력이며 현재 채택안이 아니다. Figma 반영은 MCP 한도로 차단되었다.

상태: **아래는 초기 설계 이력. 조회 상세의 과거 선택·재생을 제품에 구현했다. [현재 구현 명세](2D배치_좌표편집_과거재생_구현.md) 참고**. [독립 HTML 시안](../outputs/과거시각_재생_디자인_초안.html)에서 상호작용을 확인한다. 기존 `screen_template.html`과 실행 앱의 기능은 이번 설계에서 변경하지 않는다.

## 1. 목적과 범위

운영자가 사건 발생 전후로 이동하여 작업·설비·실적이 어떻게 달라졌는지 확인한다. 조회 기준시각은 실제 현재 시각이 아니라 적재된 데이터의 관측 시각이다.

| 적용 화면 | 동작 |
| --- | --- |
| 운영현황 | 완료·기한 도래·미해소·설비 상태, 공정 배치, 주목 작업 전체를 같은 시각으로 계산 |
| 통합 조회 | 작업·설비·사건·지연 목록에 같은 시각 적용. 검색 필터·선택 호선은 유지 |
| 작업·블록·설비 상세 | 상태·실적·이력·점유율·사건을 같은 시각으로 표시. 화면 이동 시 선택 시각 유지 |
| Settings·업로드·담당 입력 | 시간 조작 패널을 숨기고 재생 정지. 저장 대상은 현재 원본 데이터이며 과거 조회와 무관함을 안내 |
| 로그인/로그아웃 | 재생 타이머 정리. 로그인 이후 최신 데이터 기준으로 시작 |
| 서버 운영요약·AI | 사용자가 제외한 범위. 이번 설계 및 구현 대상 아님 |

과거 조회는 현재 보유한 이력으로 시점을 재구성한다. 과거에 어떤 행이 존재했는지를 재현하는 변경 버전 저장소나 감사이력 되감기 기능은 아니다. 지금 수정된 과거 실적은 수정값으로 조회되며 계획도 현재 적재된 기준계획을 사용한다.

## 2. 화면 배치

상단 내비게이션 아래, 화면 제목과 지표 카드 사이에 공통 기준시각 패널을 배치한다. 패널 자체는 고정하지 않아 작은 화면의 본문을 가리지 않게 한다.

1. **상태·시각 행:** `최신 데이터 / 과거 조회 / 재생 중 / 자료 없음` 배지, `YYYY.MM.DD HH:mm:ss KST`, `최신 기준으로` 버튼.
2. **입력·재생 행:** 조회 날짜, 조회 시각, `시각 적용`, `재생 / 일시정지`, 재생 간격.
3. **시간축:** 선택일의 이동 범위, 슬라이더, 시작/끝 시각. ±15분과 운영 시작 버튼으로 이동.
4. **블록별 공정 현황:** 각 행에 블록, 각 열에 여섯 공정을 배치하고 선택시각의 상태와 인정/계획 수량을 표시한다. 상태는 색상과 문구로 구분한다.
5. **선택 블록 상세:** 블록 또는 공정 칸을 선택하면 여섯 공정의 작업번호·상태·인정수량과 해당 시각에 발생해 아직 해소되지 않은 이상 원인을 표시한다. 시각이 바뀌어도 선택 블록과 공정을 유지한다.

기존 운영현황의 **공정 배치도는 제품에서 유지**하고, 블록별 공정 표를 추가하여 어느 블록이 어떤 공정에 있는지 함께 살펴볼 수 있도록 한다. 이 독립 시안은 블록 표와 상세를 검토하는 목적으로 공정 배치도를 간략화했다. 블록 표가 공장 도면이나 블록의 물리적 위치를 나타내는 것은 아니다. 기존 `조회 → 작업(블록)`의 정보 구조와 상태 계산을 재사용한다.

이전 초안의 ‘주요 사건’은 샘플 시나리오에서 임의로 골랐던 사건 이동 목록이었다. 사용자가 이해하기 어렵고 블록 현황을 가린다는 피드백에 따라 목록과 사건 표시점은 제거했다. 사건의 내용은 선택한 블록의 해당 공정에서 확인한다.

`현재로`나 `실시간` 대신 `최신 기준으로`를 사용한다. 복귀할 시각도 `최신 데이터 기준 YYYY.MM.DD HH:mm KST`로 함께 표시한다.

## 3. 화면 상태와 전이

| 상태 | 화면 표시 | 가능한 동작 | 전이 조건 |
| --- | --- | --- | --- |
| 최신 기준 | 청록 배지, 최신 데이터 시각 | 과거 입력·슬라이더·15분 이동 | 최신 시각보다 앞선 시각 적용 → 과거 정지 |
| 과거 정지 | 황색 배지, 과거 조회 안내 | 적용·재생·15분 이동·최신 복귀 | 재생 시작 → 재생 중, 최신 복귀 → 최신 기준 |
| 재생 중 | 초록 배지와 텍스트, 일시정지 버튼 | 정지·간격 변경·최신 복귀 | 시각 직접 조작·화면 이동·탭 숨김 → 정지, 범위 끝 → 최신 기준에서 종료 |
| 입력 대기 | 실제 적용된 시각은 유지, 적용 안내 | 날짜·시각 수정, 적용 | 입력만으로 현황을 바꾸지 않음. 수정 시작 시 재생 정지 |
| 입력 오류 | 필드 아래 오류 문구, 오류 필드 연결 | 값 수정·적용 | 오류 시 기존 적용 시각과 현황 유지 |
| 자료 없음 | `자료 없음`, 빈 상태 안내 | 화면 내 조회 안내 | 시각 조작·재생 비활성. 자료 재적재 후 최신 시각으로 초기화 |

시안은 샘플 하루 `2026-09-16 08:00~12:00`에 한정해 전이를 체험한다. 제품 구현은 전체 관측 범위를 지원한다.

## 4. 컨트롤 상세

| 컨트롤 | 상세 동작 |
| --- | --- |
| 날짜·시각 | KST 명시, 초 단위 입력 가능. 날짜/시각이 비었거나 범위 밖이면 적용 거부. 필드 오류, 허용 범위, 기존 조회 유지 안내 |
| 시각 적용 | 유효한 입력을 공통 기준시각에 적용. 입력과 조회 갱신을 분리해 입력 중 표가 바뀌지 않음 |
| 슬라이더 | 선택일의 유효 범위를 1분 간격으로 탐색. 드래그 중 시각 초안 표시, 손을 놓거나 키보드 값 변경을 확정하면 적용. 직접 입력의 정확한 초는 보존 |
| 재생 | 실제 1초마다 관측 시간 5분/15분/30분 진행. 기본 15분. 느린 브라우저에서 실제 경과시간을 따라잡는 점프는 하지 않음 |
| 재생 간격 변경 | 선택값을 다음 틱부터 반영. 시각이나 재생 상태를 초기화하지 않음 |
| 범위 끝 | 최신 기준시각에서 정확히 멈추고 종료 안내. 끝에서 재생 버튼 비활성; 자동으로 처음으로 되감지 않음 |
| 15분 전/후 | 선택 시각을 15분 이동한다. 범위 끝을 벗어나면 시작 또는 최신 기준에서 멈춘다. 해당 방향으로 더 이동할 수 없으면 버튼 비활성 |
| 블록·공정 선택 | 블록명 선택 시 해당 블록의 여섯 공정을 보여 주고, 공정 칸 선택 시 해당 공정을 강조한다. 선택한 블록·공정은 재생 중 유지한다 |
| 운영 시작 | 선택일 08:00. 해당 날짜가 관측 범위의 일부이면 유효 범위로 제한하고 안내. 운영시간 밖 관측도 직접 입력 가능 |
| 최신 기준으로 | 재생 정지 후 상한으로 이동. 실시간 새 데이터 요청 버튼과 혼동하지 않도록 최신 자료의 기준일 명시 |

제품 구현에서 선택일 범위는 `[관측 하한, 관측 상한]`과 KST 해당 날짜의 `00:00:00~23:59:59` 교집합이다. 전체 범위는 현재 작업 이력뿐 아니라 실적·사건·설비 구간·검사·재작업의 유효한 관측 시작시각을 포함해 정한다. 미래 계획과 예상 완료값은 관측 범위를 늘리지 않는다. 최신 상한은 유효한 스냅샷의 최신 `as_of`를 사용하고, 스냅샷이 없으면 유효한 관측시각 중 최신을 사용하되 `스냅샷 없음`으로 표시한다. 유효한 관측이 전혀 없으면 현재 시각으로 대체하지 않고 자료 없음으로 처리한다.

## 5. 과거 데이터 표시 계약

| 대상 | 기준시각 t에서 보이는 범위 |
| --- | --- |
| 생산실적 | `period_end_at <= t`인 증분만 합산. 진행 중 집계구간을 비례 추정하지 않음 |
| 작업 상태 | `event_at <= t`인 마지막 작업 이벤트. 같은 시각 이벤트의 정렬 기준은 원본 순서 유지로 문서화하고 임의 재정렬하지 않음 |
| 사건 | `opened_at <= t`만 현황에 표시. `resolved_at <= t`이면 해소, 아니면 당시 미해소 |
| 사건 조치 | 조치시각이 별도로 없는 최신 action 문장은 과거에 확정된 사실로 표시하지 않음. 당시 내용임을 입증할 기록만 표시 |
| 설비 과거 상태 | `start_at <= t < end_at`의 구간. 구간이 없거나 겹쳐 상태가 모호하면 자료 없음/중복 자료 안내. 최신 스냅샷을 과거 공백에 대입하지 않음 |
| 설비 최신 상태 | 각 설비의 최신 유효 스냅샷 사용, 실제 as_of를 함께 표시. 공통 상한보다 오래된 값은 갱신시각을 드러냄 |
| 설비 시간 합계 | 선택 종료와 겹치는 부분만 절단. OFFSHIFT 제외 규칙은 유지. 0시간 분모는 점유율 `—` |
| 검사·재작업 | 검사시각/보수 시작이 t 이하인 것만 표시. 보수 종료가 t 이후면 진행 중이며 완료 수량·최종 note를 과거 사실로 미리 표시하지 않음 |
| 계획·비교 | 현재 보유한 기준계획을 표시. 미래 계획 자체는 조회 가능하지만 지연 및 달성률 비교에서는 제외. 실적 날짜 귀속은 KST 종료일 |
| 예상 완료 | 최신 스냅샷의 forecast는 과거에서 `산정 근거 없음` 처리. 미래값을 당시 예측으로 둔갑시키지 않음 |

## 6. 상태 저장·권한·쓰기 화면

- VIEWER/WORKER/ADMIN 중 조회 권한이 있는 사용자는 같은 시간 탐색 기능을 사용한다. 시간 선택은 조회 상태이며 새 관리 권한을 부여하지 않는다.
- URL의 `asOf`에 KST 오프셋을 가진 ISO 시각을 보존하는 방안을 사용한다. 기존 조회 필터를 유지하며 상세 링크에도 전달한다. 매 재생 틱은 `replaceState`, 수동 적용은 `pushState`를 사용해 뒤로가기에 수백 개 기록이 생기지 않도록 한다.
- URL 범위 밖·잘못된 시각은 최신 기준으로 되돌리고 안내한다. URL 시각을 서버 저장의 기준으로 사용하지 않는다.
- Settings·업로드·담당 입력 진입 시 타이머를 정리하고 시간 컨트롤을 숨긴다. 선택값은 메모리에 유지하며 조회로 돌아오면 **정지 상태**로 복원한다.
- 데이터 초기화·샘플 복원·업로드 후 재로딩하면 이전 데이터의 시각과 범위를 그대로 신뢰하지 않는다. 새 관측 범위를 다시 계산하고 범위 밖이면 최신으로 초기화한다.
- 이 단계는 새 서버 API나 데이터 변경을 추가하지 않는다. 현재 API가 내려준 데이터와 기존 시간 계산 함수를 사용한다.
