# 호선명 정규식 검색

## 적용 화면

- **운영현황:** 항상 전체 호선의 작업·사건을 집계합니다. 호선 선택 입력은 없습니다.
- **조회:** `호선명 정규식` 입력으로 작업(블록), 사건, 생산 지연 결과의 호선을 제한합니다. 설비는 호선 공통 자원이므로 이 입력을 비활성화하고 적용하지 않습니다.

## 입력 규칙

입력값을 앞뒤 공백 제거 후 JavaScript `RegExp(입력값, 'i')`로 해석합니다. `/.../` 구분자는 넣지 않습니다. 일치 여부는 호선명과 호선 ID 중 하나에 대해 검사하며, 기본값은 문자열의 **일부 일치**입니다. 대소문자는 구분하지 않습니다.

| 입력 | 의미 |
| --- | --- |
| 빈칸 | 전체 호선 |
| `프로젝트 1` | 이름에 `프로젝트 1`이 들어간 호선 |
| `^가상.*1$` | `가상`으로 시작하고 `1`로 끝나는 이름 |
| `^V00[12]$` | ID가 `V001` 또는 `V002`인 호선 |

입력은 최대 120자입니다. 닫히지 않은 괄호처럼 유효하지 않은 정규식은 오류를 표시하고 결과를 보여주지 않습니다. 검색 중 입력 후 250ms가 지나면 결과를 갱신합니다.

## 필터 로직

1. 정규식을 화면 갱신당 한 번 컴파일하고, 일치하는 호선 ID를 `Set`으로 만듭니다. 빈칸이면 모든 호선을 통과시킵니다.
2. 작업(블록)은 블록의 `vessel_id`가 집합에 있는지 검사합니다. 사건과 생산 지연은 연결 작업의 블록에서 `vessel_id`를 찾습니다.
3. 날짜·상태·공정·일반 검색어 조건은 호선 조건과 **AND**로 적용합니다. 일반 검색어 입력은 기존의 부분 일치 검색이며 정규식이 아닙니다.
4. 설비 조회는 호선 조건을 건너뜁니다. 작업 결과의 호선별 그룹은 일치 블록을 한 번 모아 렌더링합니다.
5. 입력값은 URL의 `vessel` 매개변수에 저장됩니다. 기존 `vessel=<호선 ID>` 링크는 ID 검색으로 동작하며, 이전의 `vessel=all` 링크는 빈칸(전체 호선)으로 변환합니다.

정규식 검색은 현재 브라우저에 로드된 데이터에 적용됩니다. 호선 수가 크게 늘거나 복잡한 정규식을 자주 사용하게 되면 서버 검색 및 별도 성능 검토가 필요합니다.
